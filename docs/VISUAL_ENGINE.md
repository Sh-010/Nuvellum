# Nuvellum Visual Engine

Status: Phase 1 scaffold on `feat/visual-engine-v1`.

## Goal

Replace repetitive placeholder artwork with a deterministic visual pipeline that chooses the right visual class for each story, prefers legally reusable documentary imagery when appropriate, uses Nuvellum illustration for abstract stories, and keeps map graphics under explicit editorial review.

The Visual Engine is **not** allowed to invent documentary evidence. A generated illustration must look and be labelled as an illustration; a photo must be a real licensed image; a map must use the site's canonical geography and must not silently assert disputed borders.

## Current production state

Today the site has three image paths:

1. section placeholders under `/images/*.svg`;
2. deterministic Nuvellum SVG illustrations generated by `scripts/generate-editorial-art.mjs`;
3. article-supplied `https://` or `/uploads/` images.

The build-time SVG generator is intentionally deterministic and network-free, but it makes long feeds visually repetitive. It remains the safe fallback until the Visual Engine is connected to the newsroom.

## Phase 1: repository-side policy and discovery

Files:

- `scripts/visual/core.mjs` — visual mode policy, visual brief, license allowlist and candidate QA.
- `scripts/visual/wikimedia.mjs` — Wikimedia Commons search/metadata adapter.
- `scripts/visual/cli.mjs` — local inspection tool.
- `tests/visual-engine.test.mjs` — deterministic CI coverage.

Commands:

```bash
node scripts/visual/cli.mjs brief src/content/articles/<slug>.md
node scripts/visual/cli.mjs wikimedia src/content/articles/<slug>.md
```

The Wikimedia command is a research command, not part of the site build. Builds must remain deterministic and must never depend on an external image API.

## Visual classes

- **existing** — an article already has a non-placeholder visual; do not replace it automatically.
- **photo** — concrete news/culture/sports subject. Prefer a real reusable image directly related to the subject.
- **illustration** — analysis, opinion/ideas, or abstract technology/business concepts. Use clearly editorial illustration.
- **map-review** — geography is material and the story involves borders/routes/conflict/disaster. A map may help, but must receive explicit editorial review.
- **photo-or-illustration** — no strong automatic preference.

## Documentary-image rules

For automatic discovery, Phase 1 only trusts Wikimedia Commons metadata and allows:

- Public domain
- CC0
- CC BY 2.0/3.0/4.0
- CC BY-SA 2.0/3.0/4.0

Non-commercial, no-derivatives, unclear, missing or custom licenses are rejected automatically.

Minimum lead-image target: 1200×600, landscape aspect between 1.1 and 2.6. Remote SVG files are rejected as documentary imagery.

A Commons result is a **candidate**, not proof it depicts the event in the article. Relevance/event identity still needs an editorial/model check before the article image is changed.

## Attribution is different from reporting-source disclosure

The public article reporting-source block was intentionally removed. Visual licensing is a separate obligation.

When a CC-licensed visual is eventually published, the article will need a small image credit/caption containing the creator and license as required by that license. That is an image credit, not a disclosure of the newsroom's ingestion source.

Public-domain/CC0 images can use a quieter credit treatment, but their origin should still remain in internal visual metadata.

## Phase 2: article visual metadata

Implemented on the Visual Engine branch as an optional, backwards-compatible layer:

- `imageProvider` — `wikimedia`, `nuvellum-illustration`, or `manual`
- `imageKind` — `photo`, `illustration`, or `map`
- `imageCaption`
- `imageCredit`
- `imageLicense`
- `imageLicenseUrl`
- `imageSourcePage`

When `imageProvider: "wikimedia"` is present, validation requires the credit, license, license URL and Commons source page. The article page renders the credit quietly in the hero caption.

These fields are intentionally separate from `sourceUrls` and `sourceNote`: visual licensing is not newsroom-source disclosure.

The first five-story pilot is documented in `docs/VISUAL_PILOT.md`.

## Phase 3: newsroom integration

After repository policy is stable:

1. Build a visual brief after the article clears editorial review.
2. Choose visual class.
3. For photo-class stories, query Wikimedia Commons and score candidates.
4. Verify semantic relevance and reject old/misleading file photos.
5. For illustration-class stories, generate or use the deterministic Nuvellum fallback.
6. For map-review stories, build only from canonical country/region metadata and stop for review when boundaries are sensitive.
7. Write visual metadata to the article.
8. Publication gate validates visual metadata before merge.

The live n8n workflow stays untouched until this repository phase passes review.


## Art-direction target

The visual reference is not merely “relevant imagery.” Nuvellum should read as a premium editorial publication with deliberate art direction.

Candidate ranking therefore favors:

- strong wide composition suitable for lead crops;
- institutional, architectural, geographic, industrial, cultural or human subjects with visual weight;
- dramatic but credible natural light;
- texture, depth and restrained atmosphere;
- imagery that sits comfortably beside the ivory / wine / black editorial palette;
- photographs that feel selected by an art desk rather than pulled from a generic stock library.

The engine penalizes generic stock tropes such as handshakes, laptops, call-centre imagery, generic business meetings and glowing “AI face” visuals.

Consistency should come from **editorial taste**, not from forcing every image into the same dark treatment.
